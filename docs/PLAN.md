# План проекта fieldpose

 

## Цель
Библиотека оценки позы FTC-робота на C++17 с измеримым результатом: ошибка положения в сантиметрах или дюймах для сырой одометрии против фильтра, плюс время одного обновления.

##  1. Ядро

2. **Линейный фильтр Калмана** (`KalmanFilter`): `predict` и `update`. Тест `ConstantVelocityBeatsRawMeasurements` должен пройти.
   - Формулы: `x = F x`, `P = F P Fᵀ + Q`; `y = z - H x`, `S = H P Hᵀ + R`, `K = P Hᵀ S⁻¹`, `x = x + K y`, `P = (I - K H) P`.
   - Для обновления ковариации желательно форму Джозефа: `P = (I-KH) P (I-KH)ᵀ + K R Kᵀ`. Почему она устойчивее, надо понять.
2. **Дополнительные тесты ядра:**
   - при очень большом `R` оценка почти не меняется по измерению;
   - при очень малом `R` оценка почти равна измерению;
   - `P` остаётся симметричной и положительно полуопределённой;
   - пропуск измерения (только `predict`) увеличивает неопределённость.
3. **CI:** GitHub Actions: сборка и `ctest` на каждый push (Ubuntu, clang и gcc).
4. Первый коммит и запись в `docs/DEVLOG.md`.

##  2. Модель робота и симулятор

1. **Модель движения** позы `[x, y, theta, vx, vy, omega]` (или проще, `[x, y, theta]` с управлением по одометрии). Выбрать и записать в DEVLOG, почему такая.
2. **Симулятор** (`simulator`): робот едет по траектории (прямая, поворот, дуга, ломаная из реальных waypoints логов). Выдаёт:
   - истинную позу;
   - одометрию с накопительным дрейфом и шумом;
   - курс по IMU с шумом и смещением (bias);
   - редкие измерения позы по AprilTag (например 5–10 Гц, пропадают, когда тега нет в кадре, иногда выбросы).
3. **Слияние:** фильтр принимает асинхронные измерения (разные частоты), обновление по мере поступления.
4. **Gating выбросов:** отбраковка измерения по расстоянию Махаланобиса (порог по хи-квадрат).
5. **Данные из логов:** загрузчик, который достаёт из `*.log` waypoints и позы, чтобы траектории в симуляторе были настоящими (парсинг `RobotPose=...`, `TrcPath(...)`).

##  3. Оценка качества и оформление

1. **Оценочный прогон:** N сценариев (разные траектории и seed). Считать:
   - ошибку позы (RMSE по x, y и углу): сырая одометрия против фильтра;
   - долю времени, когда ошибка ниже порога;
   - как быстро фильтр восстанавливается после потери AprilTag и после выброса.
2. **Бенчмарк:** время одного predict+update в микросекундах (Google Benchmark). Без динамических аллокаций в горячем цикле, если получится (фиксированные размеры Eigen).
3. **Графики:** небольшой Python-скрипт на matplotlib: истинная траектория, сырая одометрия с дрейфом, оценка фильтра, метки AprilTag.
4. **README:** описание, картинка, таблица результатов (реальные цифры), раздел `Design decisions`, раздел `Limitations`.
5. **:** EKF с нелинейной моделью (поворот робота), детектор «до столкновения» по датчику расстояния (TTC), санитайзеры ASan/UBSan, `clang-tidy`.
